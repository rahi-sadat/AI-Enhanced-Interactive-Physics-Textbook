## Product and architectural boundary

The project is book-agnostic. NCTB Bangla Physics is demonstration content. The intended flow is upload → SourceAsset/PageIR → semantic BookIR → OCR/CV/SAM2 grounding → backend readiness and review → PhysicsScene → explicit simulation start with source-aligned overlay. VLM output is semantic only and cannot fabricate values or authoritative coordinates. Evidence and transient simulation exploration are separate.

Current named models are `pendulum`, `projectile`, `thin_lens`, `spherical_mirror`, `interface_refraction`, `prism`, and `dc_linear`. A broad domain contains diagrams beyond these models. Missing physical values or ambiguous topology require `NEEDS_REVIEW` and `scene: null`; do not silently invent parameters. Current `PageIRBuilder` treats the whole uploaded image as one figure. Legacy analysis/preset paths coexist with canonical ingestion.

Relevant paths: `apps/web/src/main.js`, `apps/web/src/features/` (including orchestration/review), `apps/api/main.py`, `ai/ingestion/`, `ai/evidence/grounding/`, `ai/resolution/`, `ai/ingestion/PhysicsCompiler.py`, `ai/scene_compiler/physics_compiler.py` (reexport), `engine/`, `tests/`.
